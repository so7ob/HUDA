# نور الهدى — تطبيق قرآني وثقافي متكامل

تطبيق قرآني وثقافي متكامل بهوية مستقلة، مستوحى من تجربة الاستخدام والخصائص الوظيفية لتطبيقات القرآن والمكتبات الثقافية (بما فيها تطبيق «هدى الله» المرجعي)، مع **أصول وزخارف ومحتوى مستقلة تمامًا** — دون أي استخدام للعلامة التجارية الأصلية أو أصولها المحمية.

> **حزمة التسليم الحالية:** تطبيق ويب كامل (Next.js 16 + TypeScript + Prisma/SQLite) بتجربة جوال PWA-style عربية RTL — جاهز للتشغيل والفحص فورًا في بيئة المعاينة. خطة نقل الشيفرة إلى Flutter/Android موثقة في [`docs/flutter-port.md`](docs/flutter-port.md).

## التشغيل السريع

```bash
# 1) تثبيت الحزم
bun install

# 2) إعداد قاعدة البيانات (SQLite)
bun run db:push

# 3) تغذية البيانات المرجعية (تُجلب مرة واحدة من مصادر مرخصة وتُخزَّن محليًا)
bun scripts/seed.ts

# 4) تشغيل خادم التطوير
bun run dev        # المنفذ 3000
```

> ملفات التغذية تُخزَّن مؤقتًا في `db/cache` — الإعادة تعمل دون إنترنت بعد أول مرة.

### سكربتات متاحة
| الأمر | الوظيفة |
|---|---|
| `bun run dev` | خادم التطوير (منفذ 3000) |
| `bun run lint` | فحص ESLint (نظيف: 0 أخطاء) |
| `bun run db:push` | دفع مخطط Prisma |
| `bun scripts/seed.ts` | تغذية القرآن والتفسير والمقرئين والمكتبة |

## الأمان وسلامة المحتوى
- **النص القرآني مرجعي ثابت:** لا يمكن تعديل `QuranAyah` من لوحة الإدارة إطلاقًا — الاستيراد عبر `scripts/seed.ts` الموثق فقط.
- Prisma (استعلامات معلمية) — لا حقن SQL.
- React (تهريب تلقائي) — لا HTML خام في عرض المحتوى.
- بيانات المستخدم الشخصية محلية افتراضيًا؛ لا تتبع ولا إعلانات ولا حسابات إجبارية.
- التفاصيل الكاملة: [`docs/data-sources.md`](docs/data-sources.md)

## هيكل المستودع ودورة التطوير

يتبع المستودع نموذج فروع قائم على Pull Request مع فصل صريح بين التكامل والإنتاج:

| الفرع | الدور |
|---|---|
| `main` | **الإنتاج** — آخر إصدار مستقر ومعتمد فقط؛ النشر الإنتاجي منه حصرياً بعد Tag |
| `develop` | **التكامل** — أحدث التغييرات المدمجة والمختبرة تكاملياً |
| `feature/*` `fix/*` `refactor/*` `perf/*` `test/*` `chore/*` | فروع عمل تنشأ من `develop` وتعود إليه عبر PR |
| `hotfix/*` | إصلاح إنتاجي حرج من `main`، يُعاد دمجه في `develop` دائماً |
| `archive/*` | نسخ محفوظة قبل الترحيلات الكبرى — لا تُحذف |

**الدورة:** Issue ← فرع من `develop` ← تنفيذ ← اختبارات ← PR ← CI أخضر ← دمج في `develop` ← Staging ← Release PR (ترقيم SemVer) ← `main` ← Tag + GitHub Release ← النشر الإنتاجي.

**فحوص إلزامية عبر GitHub Actions** (`.github/workflows/`): lint + typecheck + bun test + بناء standalone. البناء الحقيقي (`bun run build`) يُنفَّذ في CI، وبيئة المعاينة المحلية تعمل بوضع dev فقط.

**الأرشيفات المرجعية** في جذر المستودع (`assets.zip`, `main_db@2.zip`, `mushaf_.zip`, `res.zip`) هي مصادر البيانات الأصلية الموثقة في [`docs/data-sources.md`](docs/data-sources.md) — لا يعتمد عليها البناء وقت التشغيل؛ الأصول المستخرجة تعيش في `public/` و`db/`، والقديم محفوظ في `docs/legacy/`.
