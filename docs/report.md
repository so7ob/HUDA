# تقرير التنفيذ — نور الهدى

> تقرير صريح: ما نُفِّذ واختُبر فعليًا، وما تبقى، والقيود — دون ادعاء اكتمال أي وظيفة لم تُختبَر.

## 1) ملخص تنفيذي
بُني تطبيق قرآني وثقافي متكامل بهوية مستقلة («نور الهدى») مطابق لطابع التصميم المرجعي (فيروزي، بطاقات، شريط سفلي منحنٍ، زخارف) وبالوظائف الجوهرية المطلوبة: قراءة القرآن بوضعين، تفسير موثق، بحث شامل مطبَّع، مكتبة بمحرك محتوى مرن، أوراد وبرامج بتتبع، تلاوات آية-بآية، إعدادات كاملة، ولوحة إدارة بسير نشر وسجل تدقيق.

**صيغة التسليم:** تطبيق ويب كامل (Next.js 16/TypeScript/Prisma-SQLite) يعمل الآن في المعاينة — بخطة نقل موثقة إلى Flutter/Android (`docs/flutter-port.md`) لأن البيئة لا تتيح بناء APK.

## 2-b) التحديث: محرك رسم المصحف المدني بخطوط QCF المرخصة ✓

> طُلب: عرض المصحف **بنفس الرسم الموجود في ملفات الخط المرفقة** مع الاستفادة من قاعدة بيانات «هدى» (`so7ob/HUDA`) وملف الأصول.

| # | ما نُفِّذ | التحقق بالمتصفح |
|---|---|---|
| 1 | استيراد بيانات الرسم من قاعدة «هدى»: جدول `QuranGlyph` (88,246 رمزًا = كلمة/علامة لكل صفحة مع رقم السطر 1–15 والآية) + أسماء السور وألقابها للبحث — الأصل محفوظ في `db/sources/main_db.sqlite` والسكربت `scripts/import-huda.ts` | ✓ 604 صفحات |
| 2 | خطوط مجمع الملك فهد `QCF_P001–P604.TTF + QCF_BSML.TTF` في `public/fonts/qcf/` — تُحمَّل عند الطلب (FontFace) مع تحميل مسبق للصفحات المجاورة | ✓ |
| 3 | واجهة `/api/quran/page/[p]/mushaf`: تبني 15 خانة عرض لكل صفحة (سطور رموز + صناديق سور + بسملة) من بيانات الرسم دون أي تعديل نص | ✓ |
| 4 | العرض المطابق للمصحف المدني: قياس أطول سطر وملاءمته للعرض، توزيع تدفقي للأسطر، السطور القصيرة محاذاة يمين، علامات نهاية الآيات المزخرفة من الخط نفسه | ✓ لقطات صفحات 1، 2، 77، 106، 604 |
| 5 | البسملة الممدودة بخط الترويسة المرخص (رموز `U+FB51–FB54`) — سطر مستقل أو مدمجًا مع صندوق السورة حين تقتضي تخطيط الصفحة (كالصفحة 77) | ✓ |
| 6 | نقر كلمة يحدد آيتها (تظليل ذهبي يمتد عبر الأسطر) ويفتح الإجراءات باسم السورة الصحيح ولو كانت غير السورة المفتوحة | ✓ |
| 7 | إصلاح تحذير وصول `DialogTitle` في لوحة المشغل (Drawer) — صفر تحذيرات console | ✓ |
| 8 | إصلاحات إضافية: خط النص العثماني المعتمد (UthmanicHafs) لوضع القائمة ورؤوس السور، تبويب الوضع غير المرئي (نص أبيض على أبيض)، الأرقام العربية في بطاقة رقم الصفحة، بحث الألقاب («أم الكتاب» → الفاتحة) | ✓ |

**التوثيق:** تفاصيل المصادر والتراخيص في `docs/data-sources.md` (§2 و§7).

## 3) البنية المُسلَّمة
- **قاعدة بيانات**: 20+ كيانًا (Quran*, Tafsir*, Topic*, Reciter, Book/Chapter/Section, Plans/Logs, Favorites/Bookmarks/LastReading, Settings, Notifications, Packages, Admin/Audit) — مفهرسة وعلاقات كاملة.
- **واجهات API**: 30+ مسارًا REST (كلها اختُبرت 200).
- **بيانات مرجعية**: 114 سورة، 6236 آية عثمانية بترقيم صفحات مدني، 6236 تفسيرًا، 6 مقرئين، 7 مواضيع، كتابان مجمَّعان من القرآن (24 فصلًا)، 4 حزم محتوى.
- **أمان**: لا واجهة لتعديل النص القرآني، استعلامات معلمية (Prisma)، لا HTML خام، بيانات شخصية محلية، تصدير/استيراد بيانات.

## 4) المتبقي (بأولوية المواصفات)
| الأولوية | البند | الحالة |

| أولى | صفحات مصحفية بأسطر مرسومة (خط عثماني محفوظ الإحداثيات) | العرض الحالي يجمع آيات الصفحة بتدفق مضبوط مع حفظ الرسم — التخطيط السطري الدقيق يحتاج بيانات إحداثيات صفحات (متاحة تجاريًا/مفتوحة جزئيًا) وحقوق تُوثَّق |
| ثانية | محتوى المكتبة المرجعي (كتب تبصرة/محاضرات) | ⛔ حقوق — المحرك والإدارة جاهزان؛ يُضاف عند الترخيص |
| ثانية | تفاسير إضافية (الكبير/الجلالين…) | البنية جاهزة (`TafsirSource`) — يستوردها مدير النظام بعد الترخيص |
| ثالثة | مزامنة سحابية اختيارية | موثقة كامتداد (بيانات المستخدم محلية افتراضيًا بالتصميم) |

## 5) قيود معلنة
1. **البيئة**: منفذ واحد + لا Flutter/Android SDK → التسليم ويب PWA-style بخطة نقل.
2. **التذكيرات**: تعمل أثناء فتح التطبيق (Interval + Notification API)؛ الخلفية الدائمة خاصية أصلي.
3. **التنزيلات الصوتية**: سجل إدارة + كاش متصفح في الويب؛ ملفات كاملة في الجوال.
4. **لا تُنسخ أصول المرجع**: كل الزخارف والشعار أصلية، والمحتوى المحمي لم يُلمس.
