# دليل المساهمة — CONTRIBUTING

## قبل أن تبدأ

1. اقرأ [`BRANCHING_STRATEGY.md`](BRANCHING_STRATEGY.md) و[`WORKFLOW.md`](WORKFLOW.md).
2. اختر Issue من القضايا المفتوحة حسب الأولوية (P0 قبل P1 قبل P2 قبل P3)، أو أنشئ Issue جديد بتسع المكونات (الوضع الحالي/الهدف/الأولوية/الملفات المتأثرة/الخطوات/معايير القبول/الاختبارات/الاعتماديات/الأدلة).
3. تأكد من محيطك: `bun install && bunx prisma generate && bun test` — يجب أن تكون كلها خضراء قبل أي تعديل.

## خطوات العمل القياسية

```bash
git fetch origin --prune --tags
git checkout -b fix/<name> origin/develop     # دائماً من develop
# ... نفّذ التغيير ...
bun run lint        # نظيف إجباري
bun test            # أخضر إجباري (22+ اختباراً — أي انحدار يعني تراجعاً)
bunx tsc --noEmit   # EXIT 0 (بعد تشغيل dev/build مرة واحدة لتوليد الأنواع)
git add <ملفات محددة فقط>   # لا إضافة عشوائية للمجلد
git commit -m "نوع: وصف واضح"      # feat|fix|refactor|perf|test|chore|docs
git push origin fix/<name>:fix/<name>
```

ثم افتح PR إلى `develop` (وليس main) مع: المشكلة، الحل، الأدلة (مخرجات الاختبارات/لقطات)، ومرجع الـ Issue.

## معايير قبول الـ PR

- [ ] CI أخضر كاملاً (lint + bun test + build standalone + tsc)
- [ ] لا انحدار في الاختبارات القائمة
- [ ] الميزة/الإصلاح مُثبت فعلياً (أدلة تشغيل، لا ادعاءات)
- [ ] أي نص قرآني جديد موثق المصدر في `docs/data-sources.md`
- [ ] لا أسرار/توكنات في الشيفرة أو السجلات
- [ ] تحديث الوثائق المتأثرة (README، data-sources، audit)

## قواعد صارمة خاصة بهذا المشروع

1. **النص القرآني لا يُولَّد بالذكاء الاصطناعي أبداً** — من قواعد إباءة المشروع؛ كل نص من مصدر موثق وبتحقق بتّي.
2. **قاعدة البيانات المصدرية** `db/sources/main_db.sqlite` وأرشيفات الجذر (`res.zip` وغيرها) للقراءة فقط — لا تُعدّل ولا تُحذف.
3. الإنتاج: ممنوع `db:push:fresh` أو `--accept-data-loss`؛ قاعدة بيانات الإنتاج خارج مجلد الإصدار.
4. بيئة المعاينة المحلية تعمل dev فقط (`bun run dev` على :3000) — **البناء الحقيقي في CI** (`bun run build`).
5. الدمج عبر GitHub (PR merge commit) — لا دفع مباشر إلى main/develop حتى بملكية admin.

## أسلوب رسائل الالتزام

`<نوع>: <ملخص بفعل واضح>` — تفاصيل إضافية في الجسم عند الحاجة؛ وثّق "لماذا" أكثر من "ماذا".
