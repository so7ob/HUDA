# تحليل الفجوات — نور الهدى

> الفجوة = بعد بين الوضع المثبت (بالدليل) والوضع المطلوب لمنتج احترافي. يُحدَّث بعد كل دورة.

## 1. ادعاءات README مقابل الواقع

| الادعاء | الحكم | الدليل |
|---|---|---|
| «نص عثماني معتمد 114 سورة / 6236 آية / 604 صفحات» | صحيح ومثبت | المصحف يرندر صفحة 1، القاعدة 6236 آية، خطوط QCF في public/fonts |
| «وضع المصحف برسم QCF الأصلي» | صحيح ومثبت | متصفح + `docs/data-sources.md` |
| «مشغل تلاوات مع تعدد القراء» | صحيح ومثبت | جلسة سابقة + API reciters |
| «PWA عربية RTL بالكامل» | **مبالغ فيه** | لا service worker إطلاقًا → لا عمل دون اتصال. الموجود: manifest فقط |
| «حفظ المواضع/المفضلة/الخطط» | صحيح الشيفرة، يفتقر اختبارًا دوريًا | APIs موجودة، لم تُختبَر E2E في هذه الدورة |
| «جاهز للتشغيل والفحص فورًا» | صحيح | bun install && db (مشحونة) && dev |

## 2. فجوات وظيفية (المطلوب مقابل الموجود)

| ID | الفجوة | الأثر | الأولوية |
|---|---|---|---|
| G-1 | لا عمل دون اتصال فعلي (لا SW، لا تخزين محتوى) | الادعاء الأساسي للمنتج غير متحقق | P1 |
| G-2 | تنزيل التلاوات سجل منطقي فقط دون تخزين ملفات فعلي + تشغيل دون شبكة | ميزة معلنة غير منفذة فعليًا | P1 |
| G-3 | لا اختبارات E2E آلية (التحقق يدوي بالمتصفح فقط) | التراجعات لا تُكتشف تلقائيًا | P1 |
| G-4 | rate-limit في الذاكرة: يُصفَّر بإعادة تشغيل الخادم ولا يُشارك بين نسخ | ضعف حماية عند النشر متعدد النسخ | P2 |
| G-5 | لا نسخ احتياطي مجدول آلي (النسخ يدوي من اللوحة فقط) | خطر فقدان بيانات الاستخدام | P2 |
| G-6 | لا مراقبة أخطاء مركزية (لا سجل منظم للأخطاء) | اكتشاف الأعطال رد فعل | P2 |
| G-7 | بحث بلا فهرس دائم: إعادة تطبيع 6236 آية عند كل استعلام | زمن استجابة أطول عند نمو المحتوى | P2 |
| G-8 | تذكيرات/إشعارات مجدولة تحتاج التحقق من الاستيقاظ عند إغلاق التطبيق | ميزة الأوراد اليومية غير مكتملة | P2 |

## 3. فجوات أمنية — أُغلقت في هذه الدورة

| ID | كانت | أصبحت |
|---|---|---|
| A-1 | ignoreBuildErrors يخفي أخطاء TS (منها انهيار تشغيلي في admin chapters) | أُزيلت، tsc نظيف EXIT 0 |
| A-2 | لا حدّ من محاولات دخول الإدارة (قوة غاشمة مفتوحة) | 5/15د → قفل 120ث، مثبت E2E |
| A-3 | كوكي الجلسة secure:false دائمًا | آمن تلقائيًا في الإنتاج |
| A-4 | كلمة المرور الافتراضية بلا إلزام تغيير | كشف + banner إلزامي في اللوحة |
| A-5 | db:push مع --accept-data-loss افتراضيًا | الافتراضي آمن، العلم صريح بأمر منفصل |

## 4. قيود بيئية موثقة

- بناء Android (Flutter) غير ممكن في هذه البيئة السحابية (لا Android SDK/محاكي) — خطة `docs/flutter-port.md` تبقى المرجع، ولا يُعد PWA بديلًا عنه.
- النشر الحالي خلف بوابة http — الكوكي الآمن يُفعَّل عند HTTPS فقط (موثق في الشيفرة).
